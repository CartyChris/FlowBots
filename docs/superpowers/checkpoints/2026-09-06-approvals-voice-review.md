## Important findings

1. **Pi runtime bypasses policy evaluation for its own takeover and subagent handlers.** Source: `packages/adapters/src/pi-runtime.ts:437–456`, `packages/adapters/src/executor.ts:433–440,1041–1080`, and `packages/core/src/action-policy.ts:62–83`. Pi emits a takeover event or starts its nested agent before reaching `host.request.executeTool`; the executor's policy restriction lives in that callback. Reproduction: configure `review-risky` with an explicit `deny` rule on `run_subagent`, then have Pi call that tool. It still starts the nested model agent without evaluating the deny rule or creating an approval. Similarly, a `request_takeover` call under `read-only`, `review-all`, or an explicit deny rule immediately changes the run/computer takeover state. Subagent filtering only uses the initial mode and does not address explicit rules or later policy changes. Child ordinary tool calls still use the executor callback, so this finding does **not** claim unrestricted child shell execution. Gate the special handlers through the same current-policy and lease check before executing or emitting state-changing events; preserve their native handler behavior only after authorization. Add deterministic coverage of actual Pi dispatch, because the approval executor fixture supplies a custom runtime which directly calls the host callback.

2. **Approval polling discards an unsaved permission choice and can overwrite a successful save with a stale read.** Source: `apps/web/src/pages/ActionApprovals.tsx:31–60,71–80`. Every poll unconditionally assigns the server policy into the editable policy state, every three seconds. Reproduction: start with persisted `legacy`, select `read-only`, wait for one poll before clicking Save; the select returns to `legacy`, and Save persists that value. A second deterministic sequence is to hold an existing policy GET response, save a new policy successfully, then release the old GET: it replaces the displayed saved policy with the prior policy, and a subsequent Save can restore the prior permissions. The `stopped` flag guards notices and timer scheduling only, not the state assignments in `refresh`. Keep editable state independent from background approval polling and reject obsolete responses after saves or scope changes. Add interaction coverage with a delayed response and an unsaved change; the current immediate select-and-save E2E does not exercise either sequence. The production caller keys the component by bot ID, which mitigates a cross-bot overwrite; this finding does not assert an observed cross-bot permission grant.
